# 现有模型的云端句音构建

本轮完整文本包含 18 本内置词书、18,767 个词目、49,992 个原子义项和 99,984 条双语例句。规范化去重后有 99,940 个句子、199,880 个英美口音目标。文本冷安装已通过；这些数字不表示成品音频已经全部生成或安装。

用户已批准将本机既有的两套语音模型复制到 GitHub 免费标准构建环境，离线分批生成并打包。本机不执行模型推理，不新增模型，不调用付费内容接口。构建使用公开仓库的标准 `ubuntu-24.04` runner；模型和结果通过草稿 Release 资产传递，避免把大文件写入 Git 或 Actions artifact 存储。

## 输入和边界

- US 使用既有 `en_US-ljspeech-high`，UK 使用既有 `en_GB-cori-high`；两个模型、两个配置均按既有声音清单核对大小与 SHA-256。
- 引擎保持 Piper 1.8.0，模型配置保持原始 `en` 值。每个任务仅一个模型进程、一个推理线程；旧八进程入口和巨型恢复日志不参与构建。
- 完整读音控制覆盖 3,643 个句子、7,286 个显式口音决定，其中 1,757 个纠音、79 个暂缓。控制包保留原始 token、完整原始及纠正音素段、完整审核记录和全部当前例句引用。
- 已审核范围在 Linux 上直接使用冻结的完整音素段，不对重新音素化的字符串套用旧偏移。暂缓项优先拒绝，不加载模型或生成媒体；空段和仅暂缓而无原始音素的记录保持原状。
- 控制包以外的普通句保留实际 Linux 前端预检记录；预检不冒称观察到模型内部的音素调用。
- 草稿输入资产只包含公开控制文件、既有模型及许可材料，不包含本机凭据、私密审稿收据或原始工作目录。

## 小批验证

在包含本轮工作流的分支，手动运行现有 CI 工作流并选择 `audio_mode=pilot`。默认 `verify` 和普通应用 CI 保持完整检查。

```sh
gh workflow run ci.yml --ref YOUR_BRANCH -f audio_mode=pilot
```

小批固定八个当前句子、十六个英美音频目标，包含普通句、完整纠音句及实际暂缓拒绝控制。请求准备器验证全部 95 个公开文本分片、解压摘要、计数和完整当前引用；输入控制摘要固定在 `data/ci-audio-build-inputs.manifest.json`。

生成器只在 GitHub Linux 环境进入模型路径，并禁用其运行阶段的网络。生成结果仍标记 `GENERATED_REQUIRES_INDEPENDENT_CHECK`。独立检查器核对请求、完整策略、实际调用记录、媒体及清单摘要，并将每个 WAV、MP3 完整解码到文件末尾，检查格式、时长和音量边界。通过后的档案与检查收据以运行 ID 和尝试号命名上传草稿资源，不覆盖历史资产。

小批成功后，再依据真实耗时、内存和输出量确定后续分片及并发；不能把小批结果扩大为全库覆盖、专家发音认证或生产部署。正式包仍须经过全目标闭合、安装器、严格数据库音频检查和 H5 验收后才能发行。

## 当前缓存统计

本机已完成 100 个有界元数据核对分片：44,280 个目标仅元数据匹配，155,521 个缺少匹配，79 个暂缓，未决为零。匹配记录未经媒体校验不能直接复用；这些统计与实际成品音频验收分别记录。所有原本机文字守卫保持 128 MiB、90 秒和新增 swap 保护，100 片观测峰值 98.25 MiB，swap 增长为零。

草稿构建资源、工作分支和产品 Release 是不同状态。Native/VPS 目前仍为 `0.12.0-alpha.1`；本流程未清空或导入生产数据。
